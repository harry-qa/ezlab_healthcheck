# 판정 · 운영 기준

README 요약본의 근거. 배경 서술과 개편 이력은 커밋 `a7855d0` 이전 README에 있습니다.

## 판정 기준

- **HTTP** — 공개 경로는 2xx·3xx만 정상. 400·405·408·429·5xx 실패. 자사 도메인 401/403도 실패(예외는 `AUTH_GATED` 명시분만, 현재 비어 있음). 외부 링크는 INFO 기록만.
- **SLOW** — 응답 3초 초과. 스코어 미반영.
- **이미지** — 200만 관측된 자산은 요청 URL당 1회 능동 검증(`Content-Type: image/*` + 본문 크기 > 0). 304 정상, 제3자 도메인 제외. 판정은 실제 요청 URL 기준(Next 이미지 프록시는 폭마다 URL이 다름).
- **설치 파일** — HEAD 확인, 차단하는 CDN만 Range GET(206 + `Content-Range` + 수신 1바이트). URL 0건 수집이면 WARN.
- **인증서** — D-14 이하 WARN, D-7 이하·만료 FAIL.
- **로그인** — 버튼 렌더까지만 확인. 누락 WARN, 진입 실패 FAIL. OAuth 성공 여부는 범위 밖.
- **점검 페이지 신호** — 내부 링크의 실제 마크업에서만 검사(번들 문구·외부 링크 오탐 방지).

## 재시도

- 전체 재시도 없음. **실패한 요청에만** 백오프 2초 → 4초.
- 4xx 즉시 확정. 예외는 '지연 404' 하나 — 자사 호스트 + 멱등 GET + 응답 8초 이상이면 타임아웃 취급.
- 5xx·응답없음·타임아웃만 재시도. 회복은 INFO(스코어 미반영), 최종 실패는 WARN/FAIL.
- 예산 게이트 — 재시도가 `REPORT_SAFETY_MS`(510초)를 넘길 것 같으면 최초 실패로 확정하고 `retrySkipped: 'budget'`. 리포트 저장까지 보장하지는 않습니다.

## 오탐 방어 (고치기 전에 읽을 것)

- 네트워크 실패는 **허용 목록**으로만 인정(`ERR_FAILED`, `ERR_TIMED_OUT`, `ERR_CERT_*` 등). `ERR_ABORTED` 는 장애 아님 — 차단 목록으로 바꾸면 `_next/image` 오탐이 돌아옵니다.
- 우리가 차단한 요청은 `WeakSet<Request>` 로 제외. URL Set으로 바꾸면 같은 URL의 진짜 실패를 놓칩니다.
- 장애 지문은 **누적 교집합**(`{A,B}→{A}→{B}` 는 연속 아님). 지문 이력이 없으면 횟수 폴백 — 폴백을 빼면 판정 불가 상황에서 알림이 통째로 죽습니다.
- 자사 401/403 예외를 정규식으로 넓히면 실제 결함이 인증 게이트로 흡수돼 미탐됩니다.

## 증거

- 모든 FAIL·WARN에 증거 필수, INFO 제외. 기록은 `recordIssue()` 단일 진입점.
- 화면에 드러나지 않는 장애(API·설치 파일·SSL·네트워크)는 **진단 카드**로 렌더. 지문당 파일 1장 공유.
- `evidenceMissing` 이 0이어야 정상.

## 요청 정책

- 자사 요청에 상수 헤더 `X-Ezlab-Healthcheck: 1`(실사용자 트래픽 분리). 런마다 바뀌는 ID는 싣지 않음 — CloudFront 캐시 키 분산 우려.
- GA4·광고 beacon 차단(통계 오염 방지). 렌더에 필요한 로더는 통과.
- 일반 브라우저 `User-Agent` + 랜덤 딜레이 300~800ms(링크 검증 요청만).
- 계측 주의 — `requestCounts` 는 브라우저 요청만 셉니다. `page.request`·TTFB·TLS 핸드셰이크 제외.

## 테스트

- `tests/judgment.spec.ts` + `scripts/test_fail_streak.py` 가 판정 규칙을 운영 상태와 무관하게 고정합니다. CI에서 헬스체크보다 먼저 실행되고, 실패하면 런이 중단됩니다.
- 헬스체크 본체는 사이트 상태에 따라 결과가 바뀌어 규칙 검증에 쓸 수 없습니다.

## 운영

- 운영 이력·Pages·Slack·Issue 는 **main 정기 스케줄 실행에서만** 갱신(`IS_PRODUCTION_RUN`). 수동·브랜치 실행은 아티팩트만 남깁니다.
- 스케줄은 `17,47 * * * *`. `concurrency: health-check` 로 순차 실행합니다(gh-pages 통계 파일 덮어쓰기 race 방지).
- Slack 미리보기: `DRY_RUN=1 SLACK_WEBHOOK_URL=x HEALTH_STATUS=FAIL RECENT_STATUSES=FAIL,PASS RUN_DATETIME=... python3 scripts/notify_slack.py`
- 유지보수 스크립트는 gh-pages 워크트리에서 실행합니다.
  - `backfill_stats.py <경로>` — 집계 재구성(손상·유실 복구용). 검증 실패 시 파일을 쓰지 않고 중단.
  - `reclassify_warns.py <경로> [--apply]` — 판정 기준 변경 시 과거 WARN 정정. `--apply` 전에 dry-run 필수. 개별 실행 폴더의 `status.json` 도 함께 고칩니다(루트만 고치면 다음 백필에 되살아남).
- 변경 반영 전 A/B 게이트: `.github/workflows/ab-network-policy.yml` — 요청 증가 +10% 초과, 예산(510초) 초과, `evidenceMissing != 0`, 미완주면 실패. `workflow_dispatch` 는 워크플로 파일이 main에 있어야 트리거됩니다. 브랜치 CI 성공은 A/B 통과가 아닙니다.
- 미해결 — `ezlab.im` 정적 자산이 GET·HEAD 모두 반복 CloudFront MISS. 원인 미확정.
